\section{Background and Contributions}\label{sec:intro-background}

Proving Program Equivalence is the act of verifying that, for any input, two programs always give the same output. Formally, functions \(f\) and \(g\) are defined as equivalent if, for all arguments \(x_1\) to \(x_n\), and arguments \(y_1\) to \(y_n\) being a permutation of arguments \(x_1\) to \(x_n\): \[ f(x_1, \ldots, x_n) = g(y_1, \ldots, y_n) \]

If this can be proven, then these programs are equivalent; one of these programs can be substituted for the other without affecting the behaviour of the overall system. This has applications in a variety of fields. For example, compiler developers can use this to ensure that optimisations always preserve the intended behaviour of the original program.

Therefore, Program Equivalence is a critical field in Computer Science. However, it is a very difficult task, especially since the problem is undecidable in general. To mitigate this problem, a variety of program verifiers are being developed including Dafny~\cite{leinoDafnyAutomaticProgram2010} and KeY~\cite{ahrendtUsingKeYProver2016}. Developers can use these verifiers to make writing proofs of program equivalence easier. These verifiers automate much of the proof generation and can generate counterexamples when equivalence cannot be proven. However, in general, they still require a significant level of user assistance to complete proofs, often involving writing complicated specifications, loop invariants or auxiliary lemmas. Recently, many equivalence checkers are being developed to make proving equivalence even easier \parencite{lahiriSYMDIFFLanguageAgnosticSemantic2012,milovancevicProvingDisprovingEquivalence2023,felsingAutomatingRegressionVerification2014,godlinRegressionVerificationProving2013}.

Therefore, the aim of this project was to build EquiDafny, a new equivalence checker on top of Dafny, learning from the current state-of-the-art checkers. I chose Dafny since it is a popular tool used by Amazon \parencite{leinoDafnyAutomaticProgram2010}. Therefore, building a tool on Dafny would be highly relevant to modern software engineering projects. This is especially true since Dafny can be compiled into a variety of popular languages, including C\#, Java and Python, allowing verified code to easily be integrated into existing codebases. 

EquiDafny focuses on proving equivalence between Dafny functions only, as this provides enough complexity by itself.

To find an understanding of Dafny's capabilities, I took the program equivalence tests for the Stainless Scala verification tool \parencite{StainlessFrontendsBenchmarks} and converted them to Dafny. After attempting to prove equivalence for each pair of functions, I identified a number of challenges Dafny encounters. I will present an overview of EquiDafny with an example that demonstrates three of the challenges I identified. Below are two equivalent functions \dafnyinline{insertSortedM} and \dafnyinline{insertSorted1}. Each function generates a specified number of random numbers, and inserts them into a sorted list while maintaining its order. In both functions, the parameter `seed' is the current random generation seed, `next' is the random generation function outputting the next seed and the generated number, `count' is the number of random numbers to generate and `xs' is the current sorted list.

The first function uses the helper function \dafnyinline{insertM} to insert a single number into the sorted list while maintaining its order:
\begin{dafny}
function insertSortedM<Seed>(seed: Seed, next: Seed -> (Seed, int), 
                             count: int, xs: List<int>): List<int>
  {
  if (count <= 0) then xs
  else
    var (nxtS, t) := next(seed);
    insertSortedM(nxtS, next, count - 1, insertM(xs, t))
}

function insertM(xs: List<int>, t: int): List<int>
  decreases xs {
  match xs {
    case Nil => Cons(t, Nil)
    case Cons(hd, tl) =>
      if (t <= hd) then Cons(t, xs) else Cons(hd, insertM(tl, t))
  }
}
\end{dafny}
%
The second function uses the same structure. It uses the helper function \dafnyinline{insert1} in the same way as \dafnyinline{insertM}:
\begin{dafny}
function insertSorted1<Seed>(seed: Seed, next: Seed -> (Seed, int),
                             xs: List<int>, count: int): List<int>
  decreases count {
  if (!(count <= 0)) then 
    var (nxtS, t) := next(seed);
    insertSorted1(nxtS, next, insert1(t, xs), count - 1)
  else xs
}

function insert1(t: int, xs: List<int>): List<int>
  decreases xs {
  match xs {
    case Cons(hd, tl) =>
      if (!(t <= hd)) then Cons(hd, insert1(t, tl)) else Cons(t, xs)
    case Nil => Cons(t, Nil)
  }
}
\end{dafny}
%
The user can create an equivalence lemma for this example:
\begin{dafny}
lemma eqInsertSorted<Seed>(seed: Seed, next: Seed -> (Seed, int), 
                           xs: List<int>, count: int)
  ensures insertSorted1(seed, next, xs, count) == 
            insertSortedM(seed, next, count, xs)
{}
\end{dafny}
%
The Stainless equivalence checker can prove these functions equivalent automatically. However, the Dafny verifier is unable to do this. This is due to three challenges. 

\paragraph{First:} Generate and call helper lemmas for helper functions. The \dafnyinline{insertSortedM} and \dafnyinline{insertSorted1} functions both use the helper functions \dafnyinline{insertM} and \dafnyinline{insert1} in the same way, therefore, the Dafny verifier requires an equivalence lemma between these functions. To resolve this, EquiDafny creates and calls a helper equivalence lemma \dafnyinline{eqInsert}, under the condition \dafnyinline{count > 0} and with the correct arguments.
\paragraph{Second:} Provide a variant. EquiDafny provides a suitable variant for proving termination (\dafnyinline{count}), copied from the \dafnyinline{InsertSorted1} function.
\paragraph{Third:} Explicitly stating the induction scheme. EquiDafny provides a recursive call to the \dafnyinline{eqInsertSorted} lemma to complete the proof. 

EquiDafny can resolve these challenges. Therefore, EquiDafny can prove equivalence by generating the following equivalence lemmas:
\begin{dafny}
lemma eqInsert(t: int, xs: List<int>)
  ensures (insert1(t, xs) == insertM(xs, t))
{}

lemma eqInsertSorted<Seed>(seed: Seed, next: Seed -> (Seed, int), 
                           xs: List<int>, count: int)
  ensures (insertSorted1(seed, next, xs, count) 
           == insertSortedM(seed, next, count, xs))
  decreases count
{
  if count > 0 {
    var (nxtS, t) := next(seed);
    eqInsertSorted(nxtS, next, insert1(t, xs), count - 1);
    eqInsert(t, xs);
  }
}
\end{dafny}
%
EquiDafny can generate these lemmas using an algorithm called `Function Merging'. By exploiting similarities between the structures of function bodies, these structures can been split into their constituent parts and recursively `merged' together. The algorithm outputs the body of each equivalence lemma. It also outputs a mapping describing how the arguments of one function must be permuted to form the arguments of the other. 

EquiDafny was implemented in Scala. I tested EquiDafny on a dataset of 126 test files. This dataset is publicly available at \\\url{https://github.com/NVictor2004/dafny-equivalence-benchmarks}. Each file contains at least one pair (often multiple pairs) of equivalent Dafny functions. EquiDafny verified 70 of these tests while Dafny verified 37. Thus, EquiDafny improves the base Dafny verifier. In particular, EquiDafny is able to verify the equivalence of \dafnyinline{insertSortedM} and \dafnyinline{insertSorted1} as shown above. However, the Stainless equivalence checker can verify 93 of these tests, therefore, the state-of-the-art checker is still more performant than EquiDafny.
