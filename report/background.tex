\subsection{Dafny}\label{sec:dafny}

\footnote{simple example in each thing in the intro, maybe same example, specification is optional}
\footnote{formal definition of program equivalence}

Dafny is a popular program verifier, under active development by Amazon \cite{leinoDafnyAutomaticProgram2010}. It is primarily a programming language, containing many of the classic language features and constructs we expect from a modern programming language. However, in addition to this, it includes specification constructs, such as preconditions, postconditions and loop invariants. This allows Dafny's verifier to automatically prove theorems and that programs match their specifications. Dafny programs can also be compiled into a variety of other languages, including C\#, Java and Python, but only after Dafny has verified them. This allows verified programs to be integrated easily into existing codebases, without breaking any functionality.

Dafny's program verification heavily relies on Boogie \cite{10.1007/11804192_17}, another state-of-the-art program verifier. The verification process involves translating a Dafny program into a Boogie program; this is then translated into a series of verification conditions, which are passed to the Z3 SMT solver \cite{10.1007/978-3-540-78800-3_24}. 

Consider the following example, converted from the original Scala provided by \textcite{milovancevicProvingDisprovingEquivalence2023}. These two functions attempt to find the maximum element of a sequence of integers. The first is as follows:
%
\begin{lstlisting}[caption=\lstinline|maxR| function, label=lst:maxR]
function maxR(l: seq<int>): int
{
  if |l| == 0 then -1
  else if |l| == 1 then l[0]
  else
    var m := maxR(l[1..]);
    if l[0] > m then l[0] else m
}
\end{lstlisting}
%
The second is as follows:
\begin{lstlisting}[caption=\lstinline|maxC| Function, label=lst:maxC]
function maxC(l: seq<int>): int
  decreases |l|
{
  if |l| == 0 then -1
  else if |l| == 1 then l[0]
  else
    if l[0] > l[1] then
      maxC([l[0]] + l[2..])
    else
      maxC(l[1..])
}
\end{lstlisting}
%
The main difficulty with proving the equivalence of these two functions is that they approach the problem in opposite ways: the first function processes the list from the end to the start, while the second processes it from the start to the end. However, despite this, Dafny is able to prove equivalence with almost no help from the user using this lemma:
\begin{lstlisting}[caption=Equivalence Lemma for \lstinline|maxR| and \lstinline|maxC|]
lemma maxEquivalence(l: seq<int>)
  ensures maxC(l) == maxR(l)
  decreases |l|
{}
\end{lstlisting}
%
This lemma states that, for any sequence of integers \lstinline|l|, the function calls \lstinline|maxC(l)| and \lstinline|maxR(l)| return the same output. Therefore, by proving this lemma, Dafny can prove that these functions are equivalent. However, in this case, Dafny requires the user to explicitly provide the length of the sequence \lstinline|l| as a variant to prove termination (this lemma is proven using induction).

For this example, the Boogie translation resulted in a file almost 3350 lines long. It begins with a series of type definitions and axioms, followed by the translation of each Dafny function, and ends with the translation of the equivalence lemma, taking only around 50 lines of code. Therefore, the Dafny programming language is highly expressive, allowing users to define functions in a concise manner. Meanwhile, the Dafny program verifier is capable of proving function equivalence, but it sometimes requires user assistance.

\subsection{SymDiff}

\footnote{how exactly does symdiff work, more details, example}
\footnote{need to define the terms product program and mutual summary}

SymDiff is a differential program verifier \parencite{lahiriSYMDIFFLanguageAgnosticSemantic2012}: it works by specifying the differences between multiple programs and verifying properties about them.

SymDiff can also be used in Approximate Computing, as described in \textcite{lahiriAutomatedDifferentialProgramb}. This is where you trade off the accuracy of a program (in an acceptable manner) for improvements in performance or energy consumption. \textcite{lahiriAutomatedDifferentialProgramb} focussed on formally proving control flow equivalence under given differences, by constructing a product program, using the concept of a mutual summary, and passing it to the Boogie program verifier.

\subsection{Stainless}

\footnote{scala subset specify}
\footnote{Examples of specifications and counterexamples}
\footnote{What does matching many functions mean?}

Stainless is a verification framework that verifies that Scala programs obey their specifications \parencite{IntroductionStainless091}; when these specifications are violated, Stainless is able to provide counterexamples. Stainless performs these verifications by passing each part of the program through a series of transformations, until it can be used by the Inox solver \parencite{EpfllaraInox2026}. However, an important restriction of Stainless is that it only supports a subset of Scala's features.

One part of Stainless's functionality that is especially relevant to this work is its equivalence checker \parencite{IntroductionStainless091,milovancevicProvingDisprovingEquivalence2023}. Its ability to automatically generate equivalence lemmas for helper functions and to match many functions at once will make it a great inspiration for the rest of this project.

Consider the following example, taken from the equivalence tests in Stainless's GitHub repository \parencite{StainlessFrontendsBenchmarks}. This is also an example used by \textcite{milovancevicProvingDisprovingEquivalence2023}, which I converted to Dafny in \Cref{sec:dafny}. These two functions attempt to find the maximum element of a list of integers, by approaching the list in opposite directions:

\begin{lstlisting}[caption=\lstinline|maxR| and \lstinline|maxC| Scala functions, label=lst:maxRmaxCScala]
def maxR(lst: List[Int]): Int = {
    lst match {
        case Nil()           => -1
        case Cons(hd, Nil()) => hd
        case Cons(hd, tl)    => 
        if (hd > maxR(tl)) hd 
        else maxR(tl)
    }
} 

def maxC(l: List[Int]): Int = {
    l match {
        case Nil()                => -1
        case Cons(a, Nil())       => a
        case Cons(a, Cons(b, tl)) => 
        if (a > b) maxC(a :: tl) 
        else maxC(b :: tl)
    }
}
\end{lstlisting}
%
Stainless is able to prove the equivalence of these functions fully automatically. Therefore, its abilities will be a great inspiration for this project. 

\subsection{KLEE}

\footnote{Example}

KLEE is a symbolic execution engine that automatically generates high coverage test sets \parencite{cadarKLEEUnassistedAutomatic,ozkanKLEESmarterTest2025}. KLEE achieves this generation by simulating program execution with symbolic inputs, to explore every possible execution path a program can take. For each path, KLEE maintains the set of conditions needed for that path to have been taken, thus, if the path ends in an error, KLEE can use those conditions to generate a single test case that will create the error. Therefore, KLEE is a powerful tool, however, one of its main limitations is that the number of possible paths to keep track of can grow exponentially large when it is working with programs containing many loops and branches.
