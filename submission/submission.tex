\begin{abstract}
In this project, I explored Dafny's capabilities in proving program equivalence. I have built a tool called EquiDafny on top of Dafny to attempt to address the challenges the Dafny verifier faces to allow the user to create equivalence proofs with as little user assistance as possible. Finally, I evaluated EquiDafny against Stainless and Dafny. 

\keywords{Program equivalence \and Dafny \and Program verifier}
\end{abstract}

\section{Introduction}

Program verifiers~\cite{leinoDafnyAutomaticProgram2010} allow developers to write proofs of program equivalence, however, they require a significant level of user assistance to complete proofs, often involving writing complicated specifications, loop invariants or auxiliary lemmas. The average software developer will not have the necessary expertise to provide these, thus, these tools will be inaccessible to them. A variety of program equivalence checkers are being developed to help proving program equivalence easier~\cite{lahiriSYMDIFFLanguageAgnosticSemantic2012,IntroductionStainless091}.
\footnote{Add citations for reve and rvt, check email}

The general aim of this project is to build a new equivalence checker on top of Dafny, learning from the current state-of-the-art checkers. It decreases the level of user assistance required as much as possible, thus allowing the average software developer to better reap the benefits of using program verifiers in their work.

This project will focus on the Dafny program verifier. Dafny is a popular tool used by Amazon~\cite{leinoDafnyAutomaticProgram2010}, therefore, building a tool on Dafny would be highly relevant to modern software engineering projects. This is especially true since Dafny can be compiled into a variety of popular languages, including C\#, Java and Python, allowing verified code to easily be integrated into existing codebases. 

\section{Example}

To find an understanding of Dafny's capabilities, I used the set of program equivalence tests in the GitHub repository for the Stainless Scala verification tool~\cite{StainlessFrontendsBenchmarks}. After converting them from Scala to Dafny I attempted to prove equivalence for each pair of functions. Using this I identified a number of challenges Dafny encounters. One of the main challenges involved generating equivalence lemmas for helper functions, and calling them with the correct arguments and under the correct conditions. Since the Dafny verifier often proves lemmas through induction, further challenges included the verifier often requiring a variant to prove termination, and sometimes requiring an explicit statement of the induction scheme. 

An example that demonstrates all three of these challenges is as follows. Here are two functions called \lstinline|insertSortedM| and \lstinline|insertSorted1| that each generate a specified number of random numbers, and insert them into a sorted list while maintaining its order.

\footnote{explain exactly why everything is needed in each example, explain the challenges in detail}

\begin{lstlisting}[caption=...]
function insertSortedM<Seed>(seed: Seed, next: Seed -> (Seed, int), count: int, xs: List<int>): List<int>
  {
  if (count <= 0) then xs
  else
    var (nxtS, t) := next(seed);
    insertSortedM(nxtS, next, count - 1, insertM(xs, t))
}

function insertM(xs: List<int>, t: int): List<int>
  decreases xs {
  match xs {
    case Nil => Cons(t, Nil)
    case Cons(hd, tl) =>
      if (t <= hd) then Cons(t, xs)
      else Cons(hd, insertM(tl, t))
  }
}
\end{lstlisting}
%
In both functions, the parameter `seed' is the current random generation seed, `next' is the random generation function outputting the next seed and the generated number, `count' is the number of random numbers to generate and `xs' is the current sorted list. Each function uses a helper function called \lstinline|insertM| and \lstinline|insert1| respectively to insert a single number into a sorted list while maintaining its order:

\begin{lstlisting}[caption=...,label=lst:insertM-insert1-functions]
function insertSorted1<Seed>(seed: Seed, next: Seed -> (Seed, int), xs: List<int>, count: int): List<int>
  decreases count {
  if (!(count <= 0)) then 
    var (nxtS, t) := next(seed);
    insertSorted1(nxtS, next, insert1(t, xs), count - 1)
  else xs
}

function insert1(t: int, xs: List<int>): List<int>
  decreases xs {
  match xs {
    case Cons(hd, tl) =>
      if (!(t <= hd)) then Cons(hd, insert1(t, tl))
      else Cons(t, xs)
    case Nil => Cons(t, Nil)
  }
}
\end{lstlisting}
%

The user can create an equivalence lemma for this example, however, the Dafny verifier is unable to prove program equivalence without assistance:
\begin{lstlisting}[caption=...]
lemma equivalenceInsertSorted<Seed>(seed: Seed, next: Seed -> (Seed, int), xs: List<int>, count: int)
  ensures (insertSorted1(seed, next, xs, count) == insertSortedM(seed, next, count, xs))
{}
\end{lstlisting}
%

EquiDafny is able to generate the following equivalence lemmas to address all three challenges outlined above, allowing the Dafny verifier to prove equivalence: 
\begin{lstlisting}[caption=...]
lemma equivalenceInsert(t: int, xs: List<int>)
  ensures (insert1(t, xs) == insertM(xs, t))
{}

lemma equivalenceInsertSorted<Seed>(seed: Seed, next: Seed -> (Seed, int), xs: List<int>, count: int)
  ensures (insertSorted1(seed, next, xs, count) == insertSortedM(seed, next, count, xs))
  decreases count
{
  if count > 0 {
    var (nxtS, t) := next(seed);
    equivalenceInsertSorted(nxtS, next, insert1(t, xs), count - 1);
    equivalenceInsert(t, xs);
  }
}
\end{lstlisting}
%

To address the three challenges the lemmas require three features. EquiDafny creates the \lstinline|equivalenceInsertSorted| lemma with a call to the helper equivalence lemma \lstinline|equivalenceInsert|, under the condition \lstinline|count > 0| and with the correct arguments. EquiDafny also provides a suitable variant (\lstinline|count|), this is copied from the \lstinline|InsertSorted| functions. Finally, it provides a recursive call to the \lstinline|equivalenceInsertSorted| lemma to explicitly provide an induction scheme. 

In the next section, we describe the algorithm behind EquiDafny and how we implemented it.

\section{Design}

The main algorithm EquiDafny uses is called `Function Merging'. By exploiting similarities between the structures of function bodies, these structures can been split into their constituent parts and recursively `merged' together. This algorithm has two outputs. The first is a set of mappings between the parameters of one of the functions to the parameters of the other. These mappings describe which parameters have the same purpose across the two functions. These mappings are used to ensure arguments are inserted correctly into the function calls within the postconditions of each lemma. The second output is the body of each lemma. This includes variable declarations and calls to any equivalence lemmas with the correct arguments and under the correct conditions. Additionally, the Function Merging algorithm involves many complex technical details, including how to merge function call arguments correctly and how to merge mutually recursive functions.
